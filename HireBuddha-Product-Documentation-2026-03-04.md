## 3. The AI Workforce Hierarchy

HireBuddha introduces a revolutionary **4-tier intelligence hierarchy** that mirrors how a real organization works, but with AI at every level. This is not a chatbot. This is an **organizational structure for autonomous digital intelligence**.

```
Organization
    │
    ▼
╔════════════════════════════════════╗
║         PROCESS (C-Suite AI)       ║  ← Orchestrates the whole operation
║  "Run our monthly sales campaign"  ║
╚══════════════════╦═════════════════╝
                   │
                   ▼
╔════════════════════════════════════╗
║          AGENT (Manager AI)        ║  ← Manages specific workflows
║   "Handle all customer outreach"   ║
╚══════════════════╦═════════════════╝
                   │
                   ▼
╔════════════════════════════════════╗
║           SKILL (Specialist AI)    ║  ← Executes domain-specific tasks
║    "Draft personalized proposals"  ║
╚══════════════════╦═════════════════╝
                   │
                   ▼
╔════════════════════════════════════╗
║            ACTION (Worker AI)      ║  ← Performs individual micro-tasks
║   "Search web, write to a file"    ║
╚════════════════════════════════════╝
```

### Why This Matters

Instead of a single, monolithic AI chatbot, HireBuddha lets you build **layered AI teams** where:

- A **Process** defines the overarching business goal and orchestrates everything below it
- An **Agent** takes ownership of a specific domain (e.g., "Customer Support", "Lead Generation")
- A **Skill** provides specialized intelligence within that domain (e.g., "Handle refund requests")
- An **Action** performs atomic, tool-assisted tasks (e.g., "Search for the customer's order in our database")

**Each layer can call the layers beneath it**, creating recursive chains of intelligent behavior that can solve problems human teams struggle with. This is how you build an AI department, not just a single bot.

### Intelligent Execution Modes

Each AI entity in the hierarchy can be configured with a **reasoning mode** that determines *how* it thinks:

| Mode | How the AI Thinks | Best For |
|---|---|---|
| **ReAct** | Reason-then-Act loop | General task execution |
| **Chain-of-Thought** | Thinks step-by-step before acting | Complex analysis & writing |
| **Reflection** | Critiques its own output before delivering | High-stakes decisions |
| **Tree of Thoughts** | Explores multiple solution paths | Research & problem-solving |

## 6. The AI Mind: Memory & Intelligence

### The Four-Tier Memory System

What separates a great human employee from a mediocre one is often **memory**—the ability to remember past interactions, apply past learnings, and retrieve relevant knowledge at the right moment. HireBuddha gives your AI employees this exact capability through a sophisticated **Four-Tier Memory Architecture**.

```
┌─────────────────────────────────────────────────────┐
│                  MEMORY ROUTER                       │
│                                                      │
│  Tier 1: WORKING MEMORY                             │
│  ————————————————————————————                       │
│  In-run context. The AI's "active thoughts"         │
│  during a task. Fast, temporary, precise.           │
│                                                      │
│  Tier 2: EPISODIC MEMORY                            │
│  ————————————————————————————                       │
│  Interaction history. The AI remembers past         │
│  conversations, what was asked, what was answered,  │
│  and what it cost. Retained per user, per agent.   │
│                                                      │
│  Tier 3: SEMANTIC MEMORY (Knowledge Base)           │
│  ————————————————————————————                       │
│  Your company's knowledge, uploaded as documents    │
│  (PDFs, DOCX, TXT, PPTX). Stored as AI-searchable  │
│  vector embeddings (768-dimension Gemini vectors).  │
│  Retrieved via cosine similarity search.            │
│                                                      │
│  Tier 4: CORTEX MEMORY (Cognitive Tree)              │
│  ————————————————————————————                       │
│  Unbounded long-term context via hierarchical        │
│  tree structures. Nodes (root, knowledge, finding,  │
│  task, output, checkpoint) organize information.     │
│  Supports auto-checkpoint, resume from cursor,       │
│  and viewport-based context injection.              │
└─────────────────────────────────────────────────────┘
```

### CORTEX: Cognitive Tree Memory for Unbounded Context

Beyond the standard three tiers, HireBuddha introduces **CORTEX** — a revolutionary cognitive tree architecture that solves the LLM context window limitation.

- **Hierarchical Nodes**: Information is organized in tree structures with node types: `root`, `knowledge`, `finding`, `task`, `output`, and `checkpoint`
- **Viewport-Based Context**: Instead of truncating context, CORTEX navigates the tree and injects only the relevant viewport into each AI call
- **Auto-Checkpointing**: When context budget is exceeded, the system automatically creates a checkpoint node preserving progress summary, key facts, and next steps
- **Resume from Cursor**: Long-running tasks can be suspended and resumed exactly where they left off
- **Configurable Budgets**: Per-entity settings for max children per node (default 12), page size tokens (default 8,000), and context budget percentage (default 40%)

The CORTEX Explorer UI lets you browse, navigate, and inspect every node in the cognitive tree — giving full visibility into how your AI organizes and retrieves knowledge.

### How Memory Makes Your AI Smarter

**Before every task**, the memory router automatically:
1. Retrieves the last 10 interactions this AI had with *this specific user* (episodic recall)
2. Embeds the user's query and performs a **cosine similarity vector search** over your uploaded documents (semantic recall)
3. Injects this rich, contextual history into the AI's prompt, making its response **dramatically more relevant and personalized**

**After every task**, the system automatically:
- Saves a summary of what was asked, what was answered, the cost, and the tools used to episodic memory
- Keeps only the most recent 10 episodes per agent/user pair (auto-pruning)

### The Knowledge Base: Train Your AI in Minutes

Upload any business document—SOPs, product manuals, pricing sheets, FAQs, case studies—and your AI employee instantly knows everything in them. The Knowledge Base uses:

- **Google Gemini Text Embedding (`text-embedding-004`)** to convert documents into searchable intelligence

Your AI doesn't just have access to your documents—it *understands* them.

<a name="guardian-oversight"></a>
## 9. Guardian Oversight: Safety by Design

We believe autonomous AI must have human guardrails. HireBuddha's **Guardian Oversight System** (Human-In-The-Loop, or HITL) ensures your AI employees never make a high-stakes decision without your approval.

### How It Works

At any point in a workflow, you can insert an **approval checkpoint**. When the AI reaches this checkpoint:

1. **Execution pauses** — the AI waits
2. **You receive a notification** with a full context snapshot of what the AI was doing
3. You can **Approve**, **Reject**, or **Modify** the pending action
4. The AI continues or adapts based on your decision

### Approval States

| Status | Meaning |
|---|---|
| **PENDING** | Awaiting human review |
| **APPROVED** | AI resumes with original plan |
| **REJECTED** | AI halts or tries an alternative |
| **TIMEOUT** | Auto-response based on configured fallback |

### The Guardrail Dashboard

Every pending approval across your entire digital workforce is visible in one place. You can see what triggered the pause, review the AI's reasoning, and respond in seconds—from any device.

### Additional Governance Controls

- **Max Recursion Depth**: Limit how deeply AI processes can call sub-processes (prevents infinite loops)
- **Cost Caps**: Set a maximum spend (in USD) for any single execution run
- **Timeout Limits**: Define maximum execution time per entity (default 60 seconds, configurable)
- **Max Tool Calls**: Limit how many tools an action can invoke in a single run
- **Retry Policies**: Configure exponential backoff with customizable retry strategies for transient failures

### Multi-Tenant Architecture: Built for Organizations

HireBuddha is designed for the enterprise with a **three-level organizational hierarchy**:

```
              ┌────────────────────────┐
              │    BUDDHA COGNITIVE LAB│ (Platform)

                          │

              └───────────┬────────────┘
                          │

              │     Tenant Admin       │
              └───────────┬────────────┘
                          │
              ┌───────────▼────────────┐
              │    USERS / EMPLOYEES   │
              │   (Your team members)  │
              └────────────────────────┘
```

This allows **resellers and enterprise groups** to manage multiple client organizations under one platform umbrella, with complete data isolation between tenants.

### Role-Based Access Control (RBAC)

| Role | What They Can Do |
|---|---|
| **App Admin** | Full platform access. Manage partners, configure global pricing, manage tool registry, billing settings |
| **App User** | Platform-level access to AI features, execution history, and reporting |
| **Partner Admin** | Manage their tenant portfolio, view earnings and commissions |
| **Partner User** | Access partner-level AI features, trigger tasks, view partner reports |
| **Tenant Admin** | Full control of their organization's AI employees, billing, users, and integrations |
| **Tenant User** | Access AI features, trigger tasks, view their own execution history |

Every API endpoint is automatically guarded by role-level permission fencing. A Partner Admin from Company A can *never* see the data of Company B's tenants.

### Security Architecture

- **AES-256-GCM Encryption**: All API keys (OpenAI, Gemini, Twilio, Razorpay, etc.) and social media OAuth tokens are encrypted at rest using military-grade symmetric encryption with a master key stored in environment variables—never in the database
- **JWT Authentication**: Stateless authentication with 15-minute access token expiry and 7-day refresh tokens (stored in HttpOnly cookies, preventing XSS attacks)
- **OAuth 2.0 Login**: Sign in with **Google** or **Microsoft** accounts — no password required
- **Email Verification**: Secure email-based account verification flow for new registrations
- **Password Reset**: Self-service password reset with secure token-based email flow
- **Company Suspension**: If a partner or tenant is suspended, a middleware layer blocks *all* API access instantly—no exceptions
- **Rate Limiting**: The API Gateway enforces Redis-backed rate limits across all endpoints (configurable, default 200/minute)
- **IMAP/SMTP Validation**: Email credentials are validated via a live `NOOP` login sequence before any storage occurs

### The Integration Registry: Your Secure API Vault

Every external API key your organization uses is stored in the **Integration Registry**, an AES-256-GCM encrypted key vault within HireBuddha. Supported integrations:

<a name="unified-gateway"></a>
## 12. The Unified AI Gateway

HireBuddha's **Unified AI Gateway** is a multi-protocol gateway that serves as the single entry point for all external and internal communications. It replaces traditional microservice sprawl with a consolidated, intelligent routing layer.

### Five Interface Types

| Interface | Protocol | Endpoint | Purpose |
|---|---|---|---|
| **REST API** | HTTP | `/api/v1/*` | Domain REST passthrough proxy to backend |
| **Webhook Receiver** | HTTP POST | `/webhook/inbound` | Unified receiver for all external webhooks (Twilio, Tata Tele, Razorpay, etc.) |
| **Internal Events** | HTTP POST | `/internal/event` | Microservice-to-microservice event routing |
| **Audio Streaming** | WebSocket | `/stream/audio` | Bidirectional real-time audio (Twilio, Tata Tele, Exotel, Web) |
| **Video Streaming** | WebSocket | `/stream/video` | Bidirectional video via WebRTC SFU |

### Gateway Architecture

- **Rate Limiting**: Redis-backed rate limiting (default 200 requests/minute) across all endpoints via `slowapi`
- **Auth Middleware**: Gateway-level JWT authentication for audio/video handshake
- **Event Bus**: In-process async queue (configurable for Apache Kafka in production) with backpressure (1,000 max queued events)
- **Central AI Dispatcher**: Routes incoming events to the correct AI agent/process for execution
- **WebRTC Video**: Full STUN/TURN ICE negotiation support for peer-to-peer video sessions
- **Health & Metrics**: `/health` and `/metrics/gateway` endpoints for real-time observability

The gateway merges what would traditionally be 3–4 separate services into one, reducing operational complexity while maintaining protocol-native performance.

## 13. Artifact Management & Call Intelligence

### The Artifact Library

Every file the platform handles — whether uploaded by a user or generated by an AI agent — is tracked as an **Artifact** with full provenance metadata.

**Two Storage Origins:**
- **`user-uploads`**: Files manually uploaded by human users (documents, images, data files)
- **`system-generated`**: Files produced by AI tools and agents (generated images, videos, PDFs, call recordings)

**Each artifact records:**
- File category (`recordings`, `images`, `videos`, `documents`, `text`)
- Who/what generated it (tool name, agent, process)
- Which execution run produced it
- File size, MIME type, duration (for audio/video)
- Purpose description and custom metadata

Storage path convention: `artifact/{origin}/{company_id}/{YYYY-MM-DD}/{filename}`

### Call Intelligence

Every voice call is automatically enriched with structured intelligence:

| Component | What’s Captured |
|---|---|
| **Call Log** | Direction, status, duration, from/to numbers, provider, cost |
| **Transcript** | Word-for-word text of the entire conversation |
| **Summary** | AI-generated executive summary of the discussion |
| **Sentiment** | Overall sentiment classification (positive / neutral / negative) |
| **Audio Artifact** | The full call recording, linked and browsable in the Artifact Library |

All call intelligence data is queryable and filterable from the **Streaming Sessions** UI and the **Reports** dashboards.
